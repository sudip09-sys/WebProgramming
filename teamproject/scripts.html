Sondor · Slides 4–6

Slide 4: Game configuration

Three difficulty levels and three modes. Warm-up, Focused and Expert adjust board size and resources. Timed mode uses a countdown. Practice removes time pressure. Duel shares one device between two players. In Duel, a successful match keeps the turn. A mismatch passes it. Most pairs wins.

Slide 5: System architecture

The engine owns rules; the interface renders state. index.html and style.css define structure and appearance. engine.mjs maintains data and rule transitions. game.mjs connects events, elapsed time and rendering. Keeping the engine independent of the DOM allows Node to test the rules directly.

The engine has no dependency on the page. It receives a state object and changes that object through functions such as flip, settle, hint, and tick. The interface then updates the cards and scoreboard. This separation is what makes the engine tests possible.

Slide 6: Matching algorithm

One move compares two distinct card selections. Reject invalid or repeated selections. Store the first open card index. Compare symbols after the second selection. Keep a matching pair; temporarily lock a mismatch. A mismatch remains visible for 800 ms. The engine blocks a third selection until settle() runs.

The matching animation is an illustration. In the actual game, the engine ignores a repeated click on the same open card. The second valid selection increases the move count. When the symbols differ, the mismatch phase prevents another selection until the reveal finishes.

Eric · Slides 7–9

Slide 7: State management

Explicit phases prevent conflicting actions. Preview locks selection before the round. Playing accepts valid selections. Mismatch and Hint temporarily lock selection. Won and Lost end the round. If time expires during a mismatch, settle() cannot change the lost phase back to playing.

Slide 8: Scoring model

Consecutive correct matches increase the reward. First match: 100 points. Each consecutive match adds 25 to the reward. The reward caps at 200 points per pair. A mismatch resets the streak. A hint costs 50 points, floored at zero. Duel victory uses pair counts rather than combo points.

For example, the first two consecutive matches earn 100 and 125 points, producing a total of 225. If the next attempt is a mismatch, the following successful match returns to a reward of 100. The hint penalty cannot create a negative score.

Slide 9: Timing and accessibility

The interface accounts for real elapsed time. performance.now() measures elapsed time. Visibility changes update the countdown. Restart cancels interval and reveal timers. Buttons support keyboard input; reduced motion disables animation. The timed countdown begins after preview and continues during hint and mismatch reveals.

Likely questions and short answers

Why separate engine.mjs and game.mjs?

The engine owns the rules and state. The interface owns DOM updates and event handling. This makes the rules easier to test.

Why use Fisher–Yates?

It shuffles an array in linear time by swapping each position with a random position among the remaining choices. It avoids the unreliable distribution of sorting with a random comparator.

What prevents a third card opening?

The mismatch phase blocks flip() until settle() finishes the reveal.

How do you handle a background tab?

The interface measures actual elapsed time and updates on visibility changes. The countdown catches up instead of relying only on callback frequency.

Does the game save scores?

No. The current game keeps round state in memory and starts fresh when the page reloads.

Can two people play from different devices?

No. Duel mode shares one board on one device. Online play would require a communication service and synchronization.

What happens if time ends during a mismatch?

The phase becomes lost. settle() only acts in the mismatch phase, so it cannot restart a lost round.
