Slides 1–2 · Introduction

Hello everyone. We are Sudip, Sondor, Eric, and Abinash. Our project is Memory Match, a browser game built with HTML, CSS, and JavaScript. The basic objective is to reveal two cards and find identical symbols. The round ends when the player finds all the pairs, or when the timer expires in timed mode.

We chose a game because it gives a clear way to demonstrate the concepts from Web Programming. A click produces a visible change, but the program must also remember which cards are open, which pairs are complete, and whether another selection is allowed. This makes the project a useful example of DOM events and application state.

The game extends the familiar matching activity with difficulty levels, a preview, limited hints, and combo scoring. A player can practise without a countdown, compete against the clock, or share the same device with another player. These options reuse the same matching rules instead of creating separate games.

The project runs as static files on GitHub Pages. It does not need an account or a database. That makes it easy to open during class and easy to inspect in the repository. Our main goal is to explain how the interface and the game rules work together. Sondor will now describe the modes and difficulty settings.

Sondor

Slides 3–4 · Modes and interface

There are three modes. Timed mode asks the player to clear the board before time runs out. Practice mode removes the countdown so someone can learn the controls. Duel mode allows two players to take turns on one device. A correct match keeps the current player's turn, while a mismatch passes the turn to the other player.

Duel mode counts the number of pairs found by each player. This is different from the points total used for combo scoring. At the end, the player with more pairs wins. The game can also display a tie. It is local multiplayer, so it does not connect two computers over the internet.

Difficulty changes the board size and the resources available. Warm-up uses six pairs, a 120-second timed limit, and three hints. Focused uses eight pairs, 100 seconds, and two hints. Expert uses twelve pairs, 90 seconds, and one hint. The time limit applies only in timed mode.

Every new round begins with a three-second preview. The symbols are visible, but selections are locked during that preview. The countdown starts afterward. Changing a setting does not interrupt the current round; the new setting applies when we restart.

The HTML provides controls, a scoreboard, a progress bar, and the card board. CSS gives the cards front and back states, matching feedback, and a responsive layout. Cards are buttons, so a player can reach them with Tab and activate them with Enter. Reduced-motion preferences disable animation. Eric will explain the JavaScript behind these changes.

Eric

Slides 5–6 · Code and matching

The code separates game rules from browser interaction. The engine module creates the cards and stores the game state. The interface module connects buttons to the engine, updates the page, and manages timed callbacks. This separation lets us test the rules in Node without needing a browser.

When a round starts, the engine takes the required number of symbols and creates two cards for each symbol. It then uses a Fisher–Yates shuffle. The shuffle walks backward through the array and exchanges each position with a randomly selected position up to that point.

The flip function first checks whether a selection is allowed. It ignores clicks outside the playing phase, cards that are already matched, and a repeated click on the same open card. On the first valid selection, it stores the card index. On the second selection, it increases the move count and compares the symbols.

If the symbols match, both cards become matched. The engine increases the pair count, streak, and score, then clears the open-card list. If all pairs are complete, the phase changes to won. If the symbols differ, the phase changes to mismatch. That phase prevents a third card from opening.

The browser waits 800 milliseconds before calling settle. Settle hides the mismatched pair and returns the game to playing. In duel mode, it also changes the current player. This is why we use a phase field instead of allowing every click to change the board immediately.

The timer uses elapsed time from performance.now rather than assuming each callback arrives exactly on schedule. Restart clears the interval and reveal timeout before creating a new round. Abinash will explain scoring and show the game.

Slides 7–8 · Scoring, tests and demo

A successful match starts at 100 points. Consecutive matches add 25 points to the reward, up to 200 points per pair. For example, the first two consecutive matches earn 100 and 125 points, so the total becomes 225. A mismatch resets the streak, and the next successful match earns 100 again.

A hint reveals the board for one second. It reduces the remaining hint count and deducts 50 points, but the score cannot go below zero. The hint button is unavailable when a card is already open or when another reveal is in progress. The timed countdown continues while a hint is visible.

We ran the six automated tests included in the repository, and all six passed. They check paired-card creation, duplicate-click protection, scoring and victory, mismatch locking and duel turns, hint restrictions, timeout behavior, and preview locking. These are rule tests. They do not replace checking the layout and controls in a browser.

Likely questions and short answers

Why separate engine.mjs and game.mjs?

The engine owns the rules and state. The interface owns DOM updates and event handling. This makes the rules easier to test.

Why use Fisher–Yates?

It shuffles an array in linear time by swapping each position with a random position among the remaining choices. It avoids the unreliable distribution of sorting with a random comparator.

What prevents a third card opening?

The mismatch phase blocks flip() until settle() finishes the reveal.

How do you handle a background tab?

The interface measures actual elapsed time and updates on visibility changes. The countdown catches up instead of relying only on callback frequency.

Does the game save scores?

No. The current game keeps round state in memory and starts fresh when the page reloads.

Can two people play from different devices?

No. Duel mode shares one board on one device. Online play would require a communication service and synchronization.

What happens if time ends during a mismatch?

The phase becomes lost. settle() only acts in the mismatch phase, so it cannot restart a lost round.
