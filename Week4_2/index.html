01 / THE CONCEPT

Same string.
Different meaning.

JavaScript can update an element's contents in more than one way. The key difference is whether the browser interprets your string as markup or treats it as text.

SAFE FOR PLAIN TEXTA / 01

textContent

Reads or writes text. HTML-looking characters stay visible as characters instead of becoming elements.

01message.textContent = userInput;
WHAT THE BROWSER SHOWS
<strong>Hello!</strong>
The angle brackets are shown as text.
INTERPRETS HTMLB / 02

innerHTML

Reads or replaces the HTML markup inside an element. Tags are parsed and can create real child elements.

01message.innerHTML = trustedMarkup;
WHAT THE BROWSER BUILDS
Hello!
The strong tag becomes bold text.
i

Remember: use textContent for plain text, especially content from users. Use innerHTML only when you intentionally need HTML and the content is trusted or safely sanitized.

02 / SECURITY CHECK
!

When content
isn't trustworthy.

Cross-site scripting (XSS) is a class of vulnerability where untrusted content is interpreted as executable browser content. Putting arbitrary user input directly into innerHTML can create that risk.
